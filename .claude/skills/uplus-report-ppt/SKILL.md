# 유플러스 상품 출시 보고 PPT

`ppts/` 폴더의 기준 문서 4개(교보sam+모아진, 티빙팩, 상품출시 Process 운영안, AI구독 출시보고)를 분석해 만든 규칙이다.
디자인은 **실무형(스타일 A) 하나로 통일**한다. 임원형(표지 + Summary)은 사용자가 따로 요청할 때만 쓴다.

- 상세 디자인 수치(좌표·폰트·색): [references/design-spec.md](references/design-spec.md)
- 장표 유형과 목차 후보: [references/storyline.md](references/storyline.md)
- 분석에 쓴 기준 문서 목록: [references/sources.md](references/sources.md)
- 상품 유형(단품·Pack·Pick)과 마진 계산: [references/product-types.md](references/product-types.md)
- 도구: `scripts/read_ppt.ps1`(기준 문서 읽기), `scripts/uplus_ppt.ps1`(장표 생성·PNG 렌더링 함수)

## 꼭 지킬 것

1. **고객 PII는 절대 넣지 않는다** (조직 규칙). 이름·전화번호·주소·계정·가입번호 등은 자료에 있어도 빼고, 고객 발언은 `(20대 대학생 / 6월 FGI)`처럼 익명 속성만 남긴다.
2. **인물은 팀명·직책만** 쓴다 (예: `OTT제휴팀`, `제휴사 CEO`). 사용자가 실명을 직접 주며 넣으라고 할 때만 실명을 쓴다.
3. **수치는 만들지 않는다.** 자료에 없는 값은 장표에 `[가정]` 또는 `[확인 필요]`로 표시하고 완료 보고에 모아서 알린다. 계산한 값은 산식을 남긴다 (예: `223명 x 5,900원 = 1,315,700원`). 출처는 `*` 각주로 단다.
4. **문체**: 헤드메시지는 경어체 결론형(`~하겠습니다`, `~입니다`), 본문은 개조식(`~임`, `~함`, `→`로 근거 연결).
5. **장표당 헤드메시지는 1개**다. 본문은 12pt 이상, 각주·출처만 9pt까지 허용하고 9pt 미만은 쓰지 않는다. 내용이 넘치면 `(1/2)`, `(2/2)`로 나누거나 별첨으로 보낸다.
6. **숫자 표기**: 천 단위 콤마, 가격에는 `VAT 없음`/`VAT 포함`을 반드시 적는다. 연도는 `'25년`, 날짜는 `M/D`, 기준 시점은 `(1/25 기준)`처럼 쓴다.
7. 결과는 **.pptx만** 만들고 `UPLUS/outputs/`에 저장한다. 파일명은 `YYMMDD_상품명 상품출시 보고_v1.0.pptx`이다. 수정본은 v1.1, v1.2처럼 올리고 기존 파일은 덮어쓰지 않는다.
8. `ppts/` 기준 문서는 사내 DRM 파일이다. 읽기 전용으로만 열고, 수정·재저장하지 않으며, 내용을 외부 서비스로 보내지 않는다.

## 작업 순서

### 0. 준비 (매 실행)
- `ppts/` 파일 목록을 [references/sources.md](references/sources.md)와 비교한다. **새 파일이 있을 때만** `scripts/read_ppt.ps1`로 읽는다. 기존 규칙과 다른 점을 요약해 사용자에게 확인받고, 승인되면 이 스킬 문서와 sources.md에 반영한다. 새 파일이 없으면 다시 읽지 않는다.
- 로고 확인: `assets/logo.png`가 없으면(첫 실행) 기준 문서 오른쪽 위의 로고(`Picture 2`, 113x29pt)를 `scripts/uplus_ppt.ps1`의 `Export-UplusLogo`로 추출해 저장한다. 추출에 실패하면 로고 자리를 비워 두고 사용자에게 알린다.

### 1. 필수 정보 질문
AskUserQuestion으로 **한 번에 4개 이내**의 질문을 하고, 선택지 맨 앞에 추천 기본값을 둔다. 사용자가 모른다고 하면 기본값을 제안하고, 추측한 값은 `[가정]`으로 표시해 확인받는다.
- 상품명 / 제휴사 / 상품 구성 (단품·Pack·Pick 중 무엇인지. Pick은 **앵커 + 라이프(타 제휴사)** 구조이므로 라이프 혜택 구성과 정산가도 묻는다. [references/product-types.md](references/product-types.md))
- 보고 대상과 보고일, 출시 목표일
- 가격: 정가·판매가·정산가·할인율·자사 RS·VAT 여부
- 비교 대상: 기존 자사 상품, 경쟁사(S사/K사) 상품
- 근거 데이터: 판매건·가입자·매출·순이익과 그 출처, 기준 시점
- 프로모션·출시 전략, 협의 부서, 일정
- 첨부할 캡처·자료 파일 경로

`docs/` 등 프로젝트 안에 관련 자료가 있으면 먼저 읽고, 이미 답이 있는 질문은 하지 않는다.

### 2. 목차 제안 → 확정
[references/storyline.md](references/storyline.md)의 장표 유형 중에서 내용에 맞는 목차를 **매번 제안**하고 사용자 확인을 받는다. 기본 흐름은 `출시 배경 → 상품안 → 가격 선정 근거 → 예상 매출 → 프로모션·출시 전략 → 실행계획·진행현황 → 별첨`이다. 내용에 따라 빼거나 합친다.

### 3. 스토리라인 확인
아래 표를 보여주고 OK를 받은 뒤에만 파일을 만든다.

| # | 장표 제목 | 헤드메시지 (경어체 1~2문장) | 근거 (표·도식) | [가정]/[확인 필요] |
|---|---|---|---|---|

- 헤드메시지를 이어 읽기만 해도 보고 전체의 결론이 전달되어야 한다.
- 제목은 `{상품명} 상품 출시 보고_{주제}` 형식으로 쓰고, 별첨은 `별첨. {주제}`로 쓴다.

### 4. 장표 제작
- PowerShell에서 PowerPoint COM으로 만든다. `scripts/uplus_ppt.ps1`을 dot-source해서 함수를 쓰고, 덱별 생성 스크립트는 scratchpad에 둔다. 한글이 들어간 .ps1은 **UTF-8 BOM**으로 저장해야 Windows PowerShell 5.1에서 글자가 깨지지 않는다.
- 모든 장표에 공통 헤더를 넣는다 (`Add-UplusSlide`): 핑크 점, 제목, 구분선, 로고.
- 좌표·폰트·색은 [references/design-spec.md](references/design-spec.md)를 따른다. 기준 문서에 없는 색이나 폰트는 새로 쓰지 않는다.

### 5. 검수 (완료 확인)
1. `Export-UplusPng`로 장표를 PNG로 렌더링해 scratchpad에 저장한다(결과 폴더에는 .pptx만 남긴다). 각 PNG를 열어 직접 확인한다.
2. 체크리스트:
   - [ ] **헤드메시지↔근거**: 모든 장표에 헤드메시지가 1개 있고, 아래 표·본문이 그 결론을 뒷받침한다.
   - [ ] **수치 검산**: 합계·할인율(`1 - 판매가/정가`)·RS·예상 매출 산식이 맞고, 장표 사이에서 같은 수치가 일치한다.
   - [ ] **디자인 규칙**: 제목 위치, 핑크 점, 구분선, 로고, 폰트, 색, 최소 9pt를 지켰고 글자 넘침·겹침·잘림이 없다.
   - [ ] **보안**: 고객 PII와 실명이 없고 파일명 규칙을 지켰다.
3. 문제가 있으면 직접 고치고 다시 렌더링해 검수한다(**최대 2회**). 내용 판단이 필요한 문제(수치 출처, 메시지 방향)는 고치지 말고 사용자에게 묻는다.

### 6. 완료 보고
- 저장한 .pptx 경로 (마크다운 링크)
- 장표 목록: 번호 / 제목 / 헤드메시지
- 체크리스트 결과 (통과/수정함/미해결)
- 남은 `[가정]`·`[확인 필요]` 항목 목록
