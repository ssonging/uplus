> "가정"은 인터뷰에서 확정되지 않은 내용이며 확인이 필요하다.

## 0. 배경

- 데이터가 다 떨어진 기존 고객이, 필요한 데이터 양에 맞으면서 이득인 요금제로 바꾸도록 돕는 모바일 웹이다.
- 회사는 구독 서비스 묶음 혜택을 보여 줘서 고객이 더 비싼 요금제를 고르도록 유도하고 싶다.

## 1. 용어집

| 용어 | 정의 | 비고 |
|---|---|---|
| 요금제 변경 고객 | 핸드폰은 그대로 두고, 데이터가 다 떨어져 요금제만 바꾸는 이 통신사 고객 | **이번 범위의 유일한 대상** |
| 신규 가입 고객 | 새 번호로 처음 가입하는 고객. 핸드폰 변경으로 들어옴 | 범위 밖 |
| 번호이동 고객 | 다른 통신사에서 번호를 그대로 가져오는 고객. 핸드폰 변경으로 들어옴 | 범위 밖 |
| 기기변경 고객 | 이 통신사 고객이 핸드폰만 바꾸는 경우 | 범위 밖 |
| 요금제 변경 | 고객이 지금 쓰는 요금제를 다른 요금제로 바꾸는 것 | "구독"과 다른 뜻 |
| 구독 | 유튜브·넷플릭스·디즈니플러스·티빙 같은 **부가 서비스**에 가입하는 것 | 요금제 가입을 "구독"이라 부르지 않음 |
| 인앱 구독 | 고객이 요금제와 별도로 앱 안에서 직접 결제하는 구독 | |
| 묶인 구독 서비스 | 요금제에 포함된 구독 서비스 | |
| 대표 구독료 | 구독 서비스마다 정해진, 비교 계산에 쓰는 구독료 | 금액 미정 (열린 질문) |
| 공시지원금 | 핸드폰을 살 때 받은 지원금 할인. 약정이 따라옴 | |
| 선택약정 | 공시지원금 대신 받는 요금 할인 | |
| 약정 기간 | 공시지원금 약정 기간. 보통 6개월 | |
| 기준 금액 | 공시지원금 고객이 약정 기간 안에 이 금액 미만 요금제로 바꾸면 지원금 반환이 생기는 기준. 지원금을 받을 때 쓰던 요금제에 따라 다름 | 요금제별 금액 미정 |
| 지원금 반환 | 기준 금액 미만 요금제로 바꿀 때 고객이 내야 하는 금액 | 계산식은 4장 |

| 요금제 변경 신청 | 고객이 새 요금제로 바꾸겠다고 신청하는 것 | 기존 "구독 신청"을 대체 |

**용어 통일**
- 기존 Make 프로토타입과 `screens.md`의 "구독 신청"은 **"요금제 변경 신청"**으로 바꿔 부른다. "구독"은 부가 서비스에만 쓴다.

## 2. 역할과 목표

| 역할 | 목표 |
|---|---|
| 요금제 변경 고객 | 필요한 데이터 양을 채우는 요금제 중, 지금 내는 금액과 비교해 이득인 요금제로 바꾼다 |
| 회사 (역할이 아닌 이해관계자) | 구독 서비스 묶음 혜택을 보여 줘서 더 비싼 요금제 선택을 유도한다 |

- 이 화면을 쓰는 사람은 **고객뿐**이다. 운영자·상담사는 없다.

## 3. 핵심 업무 흐름

1. 고객이 **로그인한 상태로** 들어온다. 서비스는 고객의 지금 요금제, 데이터 사용량, 약정 정보를 이미 알고 있다.
2. 고객은 필요한 데이터 양을 먼저 기준으로 두고, 그중 가장 저렴한 요금제를 찾는다.
3. (선택) 고객이 자기가 쓰는 구독 서비스를 직접 고른다. 서비스는 대표 구독료로 "지금 요금제 + 구독료"를 계산한다.
4. 고객은 "지금 요금제 + 구독료"와 새 요금제의 전체 금액을 비교한다.
5. 고객이 바꿀 요금제를 고른다.
6. 예외 확인 (5장)
   - 지금 쓰는 요금제를 골랐으면 알리고 신청을 막는다.
   - 지원금 반환이 생기면 내야 할 금액을 보여 주고 동의를 받는다.
   - 구독 중복 결제가 생길 수 있으면 기존 인앱 구독을 직접 해지해야 한다고 안내한다.
7. 고객이 요금제 변경을 신청한다. 신청할 때 고객은 아래를 한다.
   - 변경 내용 확인
   - 약관 동의
   - 정보 입력 (입력 항목 미정)
   - 지원금 반환 동의 (반환이 생길 때만)
8. 새 요금제가 **즉시** 적용된다. 그달 요금과 데이터는 날짜만큼 나눠 계산한다.

### 고객의 선택 방식
- 기본: 필요한 데이터 양 → 그중 가장 저렴한 요금제
- 예외: 이미 돈을 내는 구독 서비스가 묶인 요금제가 전체 금액 기준으로 더 싸다고 느끼면, 더 비싼 요금제도 고른다.

### 고객이 막히는 지점
- 요금제가 너무 많아서 어떤 요금제로 바꿔야 할지 모른다.
- 자기가 매달 내는 구독료를 잘 모르는 경우가 많다.

## 4. 비즈니스 규칙

| ID | 규칙 |
|---|---|
| BR1 | 새 요금제는 신청하면 즉시 적용된다. |
| BR2 | 달 중간에 바꾸면 예전 요금제와 새 요금제를 쓴 날짜만큼 나눠 요금과 데이터를 계산한다. (예: 30일 중 20일째에 바꾸면 새 요금제 데이터의 약 1/3을 받음) |
| BR3 | 공시지원금 고객이 약정 기간 안에 **기준 금액 미만** 요금제로 바꾸면 지원금 반환이 생긴다. |
| BR4 | 지원금 반환 금액 = 지원금 × (남은 약정 기간 ÷ 전체 약정 기간). (예: 6개월 약정에서 3개월이 남았으면 지원금의 절반) |
| BR5 | 기준 금액은 지원금을 받을 때 쓰던 요금제에 따라 다르며, 고객의 약정 정보에 들어 있다. |
| BR6 | 선택약정 고객은 요금제를 바꿔도 따로 낼 돈이 없다. |
| BR7 | 지원금 반환이 생기면 금액을 보여 주고, 고객이 동의하면 변경을 진행한다. |
| BR8 | 묶인 구독을 인앱에서 이미 결제 중인 고객은 기존 인앱 구독을 직접 해지해야 한다. 서비스는 해지를 안내한다. |
| BR9 | 구독료 비교는 고객이 고른 구독 서비스의 대표 구독료로 계산한다. |
| BR10 | 고객이 지금 쓰는 요금제를 고르면, 지금 쓰는 요금제라고 알리고 신청을 막는다. |
| BR11 | 구독 중복 결제 안내는 고객이 고른 구독 서비스가 새 요금제의 묶인 구독 서비스에 포함될 때만 한다. |
| BR12 | 요금제에 묶일 수 있는 구독 서비스는 유튜브, 넷플릭스, 디즈니플러스, 티빙 4개뿐이다. |

## 5. 예외 상황

| 예외 | 처리 |
|---|---|
| 지원금 반환 발생 | BR7: 금액을 보여 주고 동의 후 진행 |
| 구독 중복 결제 | BR8, BR11: 고른 구독이 새 요금제에 묶여 있으면 직접 해지 안내 |
| 같은 요금제 다시 선택 | BR10: 알리고 신청을 막음 |

- 변경 신청 실패 처리는 이번 범위 밖이다.

## 6. 데이터 모델

```
고객 ──1:1── 지금 요금제(요금제)
 │
 ├──1:1── 데이터 사용량
 ├──0..1── 약정 정보
 ├──0..N── 고객이 고른 구독 서비스 ──N:1── 구독 서비스
 └──0..N── 요금제 변경 신청 ──N:1── 요금제(새 요금제)

요금제 ──0..N── 묶인 구독 서비스 ──N:1── 구독 서비스
```

| 엔티티 | 속성 (인터뷰로 확인된 것만) | 출처 |
|---|---|---|
| 고객 | 지금 요금제, 데이터 사용량, 약정 정보 | 서비스가 이미 앎 (로그인) |
| 요금제 | 월 요금, 데이터 양, 묶인 구독 서비스 | |
| 데이터 사용량 | 이번 달 쓴 양, 남은 양, 다시 들어오는 날, 지난 달 쓴 양 | 서비스가 이미 앎 |
| 약정 정보 | 약정 유형(공시지원금/선택약정), 지원금 금액, 약정 기간, 남은 약정 기간, 기준 금액 | 서비스가 이미 앎 |
| 구독 서비스 | 이름(유튜브, 넷플릭스, 디즈니플러스, 티빙 — 4개뿐), 대표 구독료 | 대표 구독료 미정 |
| 고객이 고른 구독 서비스 | 고객이 쓴다고 고른 구독 서비스 | 고객이 직접 선택 (서비스는 인앱 구독 정보를 모름) |
| 요금제 변경 신청 | 새 요금제, 약관 동의, 고객 입력 정보(항목 미정), 지원금 반환 동의(반환이 생길 때) | |

**값이 미정인 데이터:** 대표 구독료, 요금제 목록(개수·월 요금·데이터 양·묶인 구독), 요금제별 기준 금액, 신청 입력 항목.
화면을 만들 때는 **예시 데이터**를 쓰고 "예시"라고 표시한다. 예시 값은 그때 확인받는다.

## 7. 이번 범위에서 하지 않을 것

- 신규 가입, 번호이동, 기기변경 고객
- 운영자·상담사 기능
- 인앱 구독 정보를 서비스가 직접 가져오는 것 (고객이 직접 고름)
- 추가 데이터 구매 (비교 또는 판매)
- 인앱 구독 해지 대행 (안내만 함)
- 로그인·본인 확인 화면 (로그인한 상태로 들어옴)
- 변경 신청 실패 처리

## 8. 열린 질문

모두 "미정"으로 답을 받았고, 화면을 만들 때는 예시 데이터로 대신한다.

1. 구독 서비스별 대표 구독료는 얼마인가? (유튜브, 넷플릭스, 디즈니플러스, 티빙)
2. 요금제는 몇 개이고, 각각의 월 요금, 데이터 양, 묶인 구독 서비스는?
3. 요금제별 기준 금액은 얼마인가?
4. 요금제 변경 신청 때 고객이 입력하는 항목은? (로그인 상태이므로 무엇이 더 필요한지)

답을 받은 질문:

5. ~~데이터 사용량을 고객에게 보여 주는가?~~ → 보여 주고, 필요한 데이터 양을 고르는 필터의 참고값으로 쓴다.
